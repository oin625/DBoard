# 工作树台账

新需求与现有需求遵循同一规则：所有开发、audi调试、集成、发布和临时工作树都归入当前任务台账。仓库字段仍只保留每个工程最新开发目录，台账独立保留全部目录及创建／使用／清理记录，不因切换仓库或归档而覆盖。新版本使用新编号，不自动继承上一版所有权。

## 创建与登记一起完成

任务需要隔离工作树时，先核对原仓库与准确起点，用以下命令完成创建和登记；返回success后才在其中开发，不再分两次操作：

```sh
dboard-ai worktree create D019 --repo '/原仓库' --path '/新工作树目录' --new-branch 'feature/xxx' --start 'origin/master'
```

当前需求先前的工作树已被清理，目录不存在不等于代码未完成。核对主仓库保留的准确分支及提交，用已有本地分支恢复；不采用主仓库当前其他任务的分支，也不从旧摘要重新开发：

```sh
dboard-ai worktree create D019 --repo '/原仓库' --path '/新工作树目录' --branch 'feature/xxx'
```

临时集成／核对需要游离HEAD时用create的--detach和准确--start；它同样登记，清理前必须确认HEAD已被远端分支包含。--branch、--new-branch和--detach三选一。已完成任务不恢复普通开发，用户明确的CR可额外传--task code-review创建审查目录，不改需求状态。

CLI先校验需求和台账，再创建并保存归属；已登记的相同目录重试去重，不覆盖现有目录、不切换主仓库。若返回WORKTREE_REGISTER_FAILED，工作树目录仍保留但登记未成功：先修复台账并register --created，未登记前停止开发；不能把失败当成功。每次只创建任务实际需要的工作树，先核对可复用的本任务目录，避免反复创建副本。

## 复用与其他工具创建

复用现有工作树时只登记使用：

```sh
dboard-ai worktree register D019 --path '/实际工作树根目录'
```

确由本任务通过其他工具创建的工作树，创建后立即用同一命令加--created登记；主仓库不能登记为可清理工作树。--created是明确归属声明，不根据目录名或分支名猜测。每轮结束核对本轮所有创建／使用的目录均已登记，不只检查最新report仓库。普通report --repo自动登记使用，不能替代创建归属登记；开发仍用--repo-role development，集成／发布用integration|release，避免覆盖源开发分支。

登记只更新本机台账，不追加历史、不要求交接摘要、不上传钉钉。

```sh
dboard-ai worktree list D019
dboard-ai guide --topic worktrees
```

自定义缓存在子命令前传--cache '/实际缓存路径'；台账为缓存目录的dboard-worktrees.json，归档沿用同目录主缓存归属。

## 完结后的清理

普通开发、CR和页面任务不自动清理。用户在已完成列表展开需求，点“清理工作树”，核对预览后确认；用户明确授权CLI清理时才执行：

```sh
dboard-ai worktree preview D019
dboard-ai worktree cleanup D019 --expect-preview '<刚返回的preview_revision>'
```

仅清理已完成任务明确创建的工作树。主仓库、未提交／未跟踪文件、尚未推送、锁定／身份变化、其他未完成任务仍使用和进程占用均跳过。普通分支需正确远端跟踪关系；游离HEAD需已被远端分支包含，不能靠本地悬空提交清理。失败和跳过项显示原因，处理后再试。预览后变化必须重新核对；执行用Git原生非强制remove，不使用--force、rm -rf或删除分支。

远端保存判断基于本机远端跟踪引用，不访问远端确认，也不代表已上线；完结和上线由用户确认。忽略文件（依赖、编译产物和本地配置）随目录移除，确认前说明，需要保留的配置先移出。清理失败或超时先刷新核对，不盲重试或绕过阻塞原因。
