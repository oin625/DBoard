# D板执行反馈

D板是用户的个人工作看板，不是 Aone 或正式需求流。本机保存完整上下文，钉钉「进行时」仅为自动生成的需求总览；不要用云端正文覆盖本地缓存，也不要绕过统一同步工具上传整份缓存。复制的短指令已指定任务编号、标题和 CLI 命令，`context` 返回最新现状、缓存位置和本规则；执行已授权的这张 D单，不需要重新让用户选择任务。

使用复制命令和 `context` 返回的绝对 CLI、`item.location.cache` 缓存路径。云端 runner 要通过连接用户 Mac 的本机工具执行，不能改 runner 自己的同名文件。缺少本机访问能力时说明未回写。

## 读取和反馈

以下示例的 D014 必须替换为本次咒言指定的 D编号。

1. 执行复制内容中的 `dboard-ai context D014`，读取返回的 `context` 和 `feedback_instructions`，核对 `item.id`、`item.title`。若已经拿到该结果，无需重复执行 context；从原咒言指定的代码入口和资料开始查找。
2. 建立或切换开发分支后，反馈实际 Git 工作目录。CLI 会读取当前分支；需要验证预期分支时可传 `--branch`。
3. 每完成一轮有实质改动、排查结论或验证结果的工作，都追加进度；每次暂停、交接或结束答复前保存尚未记录的本轮进展，同一轮已保存的内容不再重复追加。按下方「简短进度规则」写，使下一个 AI 能接手。开发结束记录“开发完成，待验收”及验证结果。实际未执行的测试不能记为通过。
4. 每次反馈前重新 `show`，取得最新 `item.revision` 和标题，再调用 `report`。并发改动返回 `REVISION_CONFLICT` 时，先重读条目再决定如何反馈。

```bash
dboard-ai --cache <本机缓存路径> report D014 \
  --expect-title 'show 返回的实际标题' \
  --expect-revision 'show 返回的 revision' \
  --repo '/实际 Git 工作目录' \
  --summary '接口已实现，本地测试通过，待上游联调。' \
  --details '下一步：测试环境联调；开发完成，待验收，尚未上线。' \
  --event-id '本次任务内唯一的反馈编号'
```

需求概括缺失或改造范围有变化时，可额外传 `--overview '一两句话概括当前需求范围'`（单行，最多 120 字）；概括只说明需求范围，不写路径、过程或整份咒言。已有概括且范围未变时不用反复更新，也不需要用户另填一份材料。概括与进度可分别反馈。

仓库与进度可以分开反馈：只传 `--repo` 记录仓库和分支，传 `--summary` 和可选 `--details` 追加记录（旧参数 `--progress` 等同 `--summary`）。多个仓库各自反馈；同一 Git 仓库的主目录和 worktree 只保留最新反馈的开发目录与分支，历史留在进度中。分支展示用工程名，不把多个工作目录当作多个工程。迁移、清理或切换工作目录后须回写实际仓库与分支；旧目录已不存在且确认代码移至新目录时，用 `--repo '/新目录' --replace-repo '/原记录目录'` 明确替换。仅阅读参考仓库不必反馈为开发仓库，不能把其他任务当前所在的分支当成本需求分支。CLI 不创建或切换 Git 分支；这些操作属于原开发任务。

相同反馈重试时保留原参数和同一个 `--event-id`；不同反馈用新编号。工具会防止重复追加，不要通过改写整份 Markdown 绕过 CLI。

## 简短进度规则

每条修改记录分为「一句话概括」和可选「明细」。D板默认只显示概括，点击该条明细才展开；钉钉只展示需求概括和最新有效进度；完整历史、明细、咒言、图片、群聊和工程分支留在本机，后续 AI 通过 `context` 仍可读取。新增变更尚无对应反馈时，总览显示待处理提示。仅记录仓库分支、修改明细或零碎等本地资料，总览未变就不上传。

- 先用 `--summary` 写一句话结果，通常 20～60 字，最多 120 字。说清本轮做了什么及当前关键状态，不塞实现清单、路径、日志或全部待办。必要时在概括保留「待联调／待验收／未上线／阻塞」。
- 再按需用 `--details` 写接手所需的关键事实：最先要做的 1～2 件事、验证范围和结果、重要阻塞及资料入口。通常 1～3 句、100～200 字以内；简单记录可省略明细，不凑字数。支持多行文本。
- 概括和明细都只写本轮变化；不重复需求背景、固定规则、完整实现清单、排查过程或之前未变化的进度。详细证据引用已有资料，确有必要时补项目文档。仓库和分支由 `--repo` 反馈，正文不重复绝对路径。
- 实际未执行的测试不能写为通过；沿用上轮验证要明确说明。开发完成、测试通过、用户验收和上线是不同状态，保留影响接手的未提交、待验收或不确定事实。

例：概括 `批量查询优化已提交，回归通过，待真实环境联调。`
明细 `55 项回归通过；真实 MySQL SQL、锁和耗时尚未验证。下一步先做 500 条联调，再定调度参数。详见已有实施文档。尚未上线。`

## 开发核验与调试页

先看 `item.debug_page_not_needed`：为 true 时，用户已手动选择无需调试页，不创建、更新或删除页面，也不自行撤销；最新选择覆盖旧咒言和旧复制指令的建页要求。它只免除页面，后端核验、接口测试和人工联调仍按需进行；通过 `development-complete` 和普通概括／明细记录验证，不回写页面就绪或页面试调阶段。追加变更不会自动撤销选择，已有页面和结果留作参考，用户撤销后再接续页面任务。

`context --task debug-page` 是用户明确发起的 audi 调试页面任务。读取返回的 `debug_instructions`（来自 [调试页规则](references/debug-page.md)），核验后端开发后在 audi `/test-console` 增加模块入口；开发完成后仍需接续这项页面任务。AI只先调能独立验证的部分，最终内部／外部联调测试由用户协调进行。页面及AI可调部分已完成，剩余需人工联调时，交接后直接反馈，不重复建设或反复尝试外部条件。

通过 `report --stage` 记录 `developing`、`development-complete`、`debug-page-ready` 或 `testing-passed`；正向核验结果须有一句话概括和必要的实际依据明细。普通开发任务确认实现完整时也可记录 `development-complete`，不因此自动创建调试页。页面用 `--debug-page` 回写实际路由，确认可访问后可补 `--debug-url`。`testing-passed` 仅表示AI能独立验证的部分通过，必须记录已测、未测和待人工联调事项，不能表示整体联调完成。这些是执行结论，独立于用户完成、验收和归档；需求变更后旧结论需重新核验。代码后来改变或发现失败时主动回退可靠阶段。

## 接手续做

“复制现状”只复制读取命令。执行 `context` 时才读取原咒言、分支、全部进度和追加变更，并返回完整反馈规则；命令生成后新增的进度也会读到。检查实际仓库、当前分支和未提交改动，结合原咒言、追加变更和最新进度确认本次需求中明确、尚未完成的事项；追加变更与原咒言冲突时，以后续变更为准。未记录进度不等于未开发，缺失的现状要查代码和执行结果，不能编造完成情况。

只有明确的未完成事项才继续执行。没有可继续执行的待做事项时，直接向用户反馈现状并结束，不重复开发，也不自行新增需求、重构或优化。开发已完成且只待用户验收时，报告“开发完成，待验收”；缺少联调环境或外部条件时说明阻塞，不把等待状态视为再次开发的理由。已有验证充分且代码与条件未变时，无需重复测试。有新的核验结论按简短进度规则写回；现状未变且无新进展时，不追加重复记录。

存在追加变更时，`show` 的 `item.changes` 返回各条变更编号和咒言。复制命令带 `--change C001` 时，`context` 会指定“本次追加变更 C001”；本轮在已有实现上处理该条变更，原咒言作为背景；概括以 `[C001]` 开头，明细再写必要的待做和验证信息，让后续 AI 能区分各轮变更。保留此前尚未完成的测试与验收，不能将历史变更都当作重新执行的任务。

`context` 返回“本轮版本 2.0”等说明时，原版已经归档，上一版咒言、仓库与进度仅作为背景。本轮按新的改动要求在已有代码上继续，核对并反馈本轮的实际分支，只把本轮改动和验证结果写到复制指令指定的新 D编号；不要重做原版，也不要把历史成果记作本轮完成。

交接记录直接追加到需求面板的进度，不要求用户再填一份交接文档。多条记录按保存顺序阅读，后来的结论补充或更新前面的结论。纯问答且没有新的执行进展时无需重复追加相同记录。

## 确认结果

正常输出和错误均为 JSON。检查 `success`、`local_saved`、`sync`，不能只看命令有没有输出。

- `success: true` 表示本次请求成功；`duplicate: true` 表示此前已保存相同事件。
- `sync.status: unchanged` 表示总览未变，已跳过远端上传，本地反馈正常保存；它不是同步失败。手动 `dboard-ai sync` 可重新发布总览。
- `local_saved: true` 且同步失败，表示本机已更新，钉钉未同步成功。需要重试同步时用 `dboard-ai sync`，无需再追加同一进度。
- 自定义缓存或 `--no-sync` 的结果为 `sync.status: skipped`，只能报告本地保存成功。
- 找不到条目、标题不符或条目已完成时，停止该次回写并说明原因，不新建替代条目。

反馈授权仅覆盖这张需求的仓库、分支、进度与开发调试结论。需求状态、优先级、周期、删除和完成归档仍由用户决定。CLI 本身也只提供上述反馈命令。

`dboard-ai --help` 查看命令参数；`dboard-ai guide` 可直接读取本 Skill。
