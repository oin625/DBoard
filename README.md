# DBoard — Mac 菜单栏个人工作台

D板把个人需求、零碎事项、开发工具与后台任务状态放在一个本机工作台里。
数据仍由各自来源维护：手工 D单来自本地缓存，正式 PRD 来自 ReqFlow，发布与 Audi 日志由内嵌网页承载。

开发需求使用 D001、D002 等编号；线上排查单使用 P001、P002 等独立编号。编号只根据正式条目和结构化关联递增，不扫描日志或流水号中的相似文本。

## 当前入口

菜单栏只保留 D板图标；需求流和 BizMap 从 D板入口打开，需求流也可使用快捷键。
10 个登记模块，加上 D板主面板；钉钉值守关闭时隐藏待回复入口。

| 功能 | 能力与数据源 |
|---|---|
| D板主面板 | 概览、需求、今日零碎、历史；新增编辑、优先级、状态、进度、归档删除、历史未完成事项顺延；读取 `~/.claude/demand-center-cache.md`，监听文件变化与同步钉钉 |
| ReqFlow 需求流 | 我的需求、组内分栏、详情与流转、交付物与附件、开发交付中明确声明的工程与分支、状态推进、项目表同步 |
| BizMap 业务地图 | 服务分组、关键词路由、相关 D单/PRD、服务详情、基线分支与近期变化、文档跳转；数据来自 `~/.claude/bizmap-cache.json` |
| 应用发布台 | 内嵌 Audi `/app-release`，由 Audi 页面承载制品、预发/线上发布等业务能力 |
| Audi 日志 | 内嵌 Audi `/logs-hist` |
| Audi 首页 | 内嵌 Audi 首页；三页共用窗口，在本次运行中各自保留网页和置顶状态 |
| 剪切板历史 | 本地文本、代码、URL、图片与文件；搜索、置顶、多选合并、回写、清洁 URL；敏感记录过期、历史上限；本地 SQLite |
| 打开活动监视器 | 从工具列表、常用入口或命令面板打开 macOS 活动监视器；D板不再采集系统资源或给出重启建议 |
| Skills / Agent 环境 | Skills 搜索与治理、健康与重复定义、启停归档；MCP、Hooks、Agents、Context；重开时一分钟内复用扫描结果，手动刷新立即重扫 |
| 科技资讯 | 科技热点、原文与评论、AI 中文编译、评论翻译、历史与清理 |
| 钉钉待回复 | 候选回复、编辑审批发送、配方与白名单；值守开关关闭时停止轮询并隐藏入口 |

附属能力：引擎心跳、待处理聚合、Chrome Cookie Bridge 登录桥接、一键运维「刷新抖音评价 Cookie」、入口使用记录。
抖音 Cookie 按最近一次成功刷新后 30 天估算到期；最后 7 天及过期后每天在首页「待处理」显示提醒，点击可刷新，成功后收起。失败或取消不会重置倒计时；成功时间单独持久保存，兼容已有成功记录。其余时间保留在「更多操作」，入口显示预计剩余天数。倒计时随跨日、唤醒及打开应用更新，不轮询 Cookie 或 Redis。
运维执行继续使用明确确认、进度、日志、取消与结果反馈。

今日规划（Ctrl+O）、Codex 供应商切换（⌥C）、A股行情及内存监控已移除；历史本地监控数据保留，停止采样与更新。

## 窗口与设置

- 点击 D板图标快速查看概览；浮层顶部「打开工作窗口」按钮或下拉/双击标题可进入独立工作窗口。
- 工作窗口按「概览 / 需求 / 零碎 / 历史」导航；首屏显示紧急、进行中和今日零碎统计；统计下方直接展示今日零碎列表，可添加、勾选和编辑事项；点击添加才展开并聚焦输入框，首页空列表只保留一行轻量添加入口，不显示空提示和多余边距；待处理为空时整块隐藏，直接展示需求。模块通过快捷键、侧栏或命令面板打开，打开模块时保留工作窗口。
- 工作窗口点击外部保持打开，工具栏可以置顶，按窗口分别持久化选择。剪切板和 Audi 继续保留各自的快捷浮层与保持打开行为。
- Esc 先退出命令面板、详情、搜索或选择等局部状态；输入编辑和模态表单优先处理自己的按键。快捷浮层收起时避免抢走刚切换到的外部应用焦点。
- 首页及需求页的每张 D单卡片提供「咒言」入口：提供「代码入口 / 可能有用的资料 / 要做什么」三个主要模块，另有「补充说明（选填）」；填写咒言时「要做什么」必填，支持保存和「保存并复制」，复制统一生成最新现状的读取指令；代码入口和可能有用的资料会根据内容换行并自动增高，长链接完整换行显示，主要空间留给「要做什么」；复制时为服务/流程描述、代码路径和文档线索补上查找阅读指令，按顺序组装并省略空白部分。旧版改造意图和自由文本完整保留在「要做什么」中；新建/编辑需求表单使用相同输入项。补充说明填写文档之外的范围、约束或处理偏好，旧版为什么改和特殊规则合并显示并保留原文；输入框随内容自动增高，长表单可滚动，复制时省略未填的小标题；所有输入留空可清空咒言。卡片的「复制现状」统一复制需求编号、CLI context 读取命令和回写要求等几行短指令；AI 执行命令时取得原咒言、分支、全部进度、追加变更与完整反馈规则，后续新增进度也能读到；展开后可添加独立的「变更咒言」，每条保留编号，复制这次变更时通过命令的 --change 参数指定本轮是在已有实现上修改，保留未完成的测试与验收；无需填写咒言也可使用。复制时自动附上 D编号、标题和 CLI 入口，缓存路径与完整执行反馈 Skill 由 context 返回，要求执行 AI 每轮有实质进展、暂停或交接前简短记录本轮变化、下一步和验证结论，通常100～200字、原则不超过300字；复杂交接以能接手为先，关键限制保留，详细方案与证据引用资料，同一轮已保存的进展不重复追加；执行 AI 可通过 `dboard-ai` 反馈实际仓库、分支、进展和验证结果（详见 [CLI 用法](Tools/README.md)），无需用户填写关联信息。内容随需求写入本地 Markdown，沿用同步与归档；保留 Markdown、代码缩进和空行。保存失败保留输入，同一咒言被其他编辑更新时拒绝覆盖，取消未保存修改前提示确认。
- 「历史 → 归档需求」读取钉钉已完成文档，支持搜索、展开原咒言和进度，读取失败保留本机缓存。点击「开启 2.0」生成新 D编号，继承代码入口和资料，只填本轮改动；上一版咒言、仓库、分支、变更和进度保存为背景，CLI 会说明在已有实现上开发新版本并仅回写新需求。2.0 归档后可继续开启 3.0；已有后续版本时直接打开它。误归档可「撤销归档」，保留历史快照，恢复原编号、咒言和进度为进行中，重新开始周期；恢复前检查编号和需求流关联是否已被占用。
- 新增、编辑需求、咒言、变更和群聊使用统一的编辑面板；从菜单栏浮层进入编辑时自动打开稳定的工作窗口，刷新卡片不会销毁编辑器。新增需求关闭后保留草稿，追加变更优先显示本次输入，旧变更按需展开。咒言和变更支持 ⌘S 保存、⌘↩ 保存并复制；群聊支持方向键浏览、回车选择、⌘↩ 完成关联。
- 需求卡片和已完成卡片支持「代码审查」：复制短指令交给新的 AI，按原咒言、全部变更与真实开发提交范围独立审查整体实现；默认只审查，结论以一句话概括和按需明细记回，绑定实际代码版本，不混同测试验收。CR规则随 dboard-feedback 打包，无需另装 skills。归档CR单独记录，保留原快照和旧版本关联。
- 每张需求可关联一个主要钉钉群聊及多个次要群聊，也可全部留空。整个关联区域可点击，在同一窗口管理主要群、次要群和移除操作；搜索不会丢失已选群，群列表短期复用，手动刷新立即重读。展开卡片点「关联群聊」，或在新增/编辑表单中选群；按群名搜索真实群列表，保存群 ID 区分同名群，新建草稿保留选择。复制现状仍是短指令，CLI show/context 返回关联与读取近期消息的只读命令；AI 仅在用户要求或信息不明确时参考主群，再按需参考次要群，将相关新结论及群名/消息时间简短记入进度。关联本身不会后台拉取消息。
- 咒言的「要做什么」和追加变更支持图文混排：点击「添加图片」、粘贴截图或拖入图片，双击看原图。图片副本保存在本机 ~/.claude/dboard-images/，引用随文字进入草稿和正式记录；移走原文件不影响使用，草稿仍须保存或添加后才对 AI 生效。CLI show/context 返回图片路径及是否存在，context 引导 AI 用本机工具实际读图；图片缺失时保留引用并明确提示。
- 展开首页或需求页的需求卡片时，进度历史默认只展示最新追加的一条；多条记录下方提供省略号「查看全部记录（N 条）」入口，展开后按最新在前查看全部，也可收起。收起需求再打开时恢复只显示最新一条；新增进度和 AI 读取的完整记录继续保留。
- 新增和编辑需求、进度及零碎事项，写入失败时保留输入并显示提示；写入成功后才更新界面并安排同步。
- 概览的「紧急」「进行中」会打开对应筛选；需求页支持按编号、名称、项目、分支、进度搜索和状态筛选。展开需求后显示 ReqFlow 快照时间与开发交付声明的工程。
- 历史未完成零碎按「原日期 + 原文」精确定位，可在今日列表直接勾选、编辑、备注、删除，改动写回原日期；内容已变化或无法唯一定位时拒绝写入。改过的行会带本地标识 `<!-- todo:UUID -->`，同步到钉钉时会去掉。删除需求或零碎后可在底部一键恢复。
- 日期新写入 `2026-11-19`，旧的 `11.19` 继续兼容；截止显示按自然日计算，逾期显示「逾期 N 天」。描述支持多行。
- 钉钉同步改由随 App 打包的 `sync_dboard.sh` 执行（需重新 `./install.sh`）：跨进程单飞、上传固定快照，只有退出码为 0 且返回 `success: true` 才记录 `synced` 与内容 hash；同步期间本地有改动会自动再同步。失败状态保留在底栏，不会被刷新覆盖。
- 完成并归档：远端确认成功前不移除本地；先在 `~/.claude/dboard-archive-journal.json` 记录快照，结果不明时要求先核对，避免重复追加；已写入但本地移除失败时，重试只处理本地。
- 项目表同步只按已确认的「需求 ID → 记录」（`~/.claude/dboard-aitable-links.json`）或唯一的完全同名记录写入；名称相近时弹出确认，可选关联到某条记录或新建；查询失败时不做任何写入。
- 交付物上传：选了附件但附件上传或保存失败时，整体不提交，表单和附件保留，可直接重试。
- ⌘, 打开标准设置：通用、外观、常用入口、快捷键、剪切板、使用记录；首页底栏的更多菜单也可直达「外观」。蓝靛（默认）、暖砂、石墨、透青四种皮肤提供深浅色预览，点击立即切换并保存在本机，可恢复默认。首页、查看全部、⌘P 卡片、新增和详情窗口统一换肤，保留草稿、选择与键盘焦点；状态、错误和紧急程度保留业务颜色。字体另有 8 种选择，普通界面文字、表单及咒言输入框即时跟随字体设置；编号、路径、分支和代码保留等宽字体。切换字体保留输入、图片和光标，中文候选词上屏后再应用新字体。
- 使用记录统计近 14 天的入口触发次数，覆盖模块、主面板和运维；快捷键的呼出和收起都可能记数，不能理解为任务完成数。

默认全局快捷键，可在设置中修改、关闭或恢复：

## 首页与需求流关联

需求流将「承接人验收完成」（CPYSWC）的需求归入默认折叠的「我的已完成」，不再计入「我的进行中」或「我的待办」候选；验收中仍属于进行中。已完成需求仍可搜索、展开或从组内历史查看，不自动修改正式流程或个人 D单状态。

在概览或需求页点击「新增需求 → 选择待办需求」，按编号、标题或状态搜索「我的待办」（待我处理、我在跟进）和「组内需求」。选择后带入正式标题；已填写的个人标题、项目、分支和计划保留。创建后定位到新 D单；编辑已有 D单也能选择、更换或解除关联。

关联按正式需求 ID 保存为本地 Markdown 的「需求流」链接，随编辑、优先级移动、同步和归档保留。已关联的候选显示对应 D单，点击打开已有任务；创建和保存会重新检查当前本地文件，避免重复关联。不会依据名称相同自动合并。

D单卡片显示关联编号和需求流快照中的正式状态，点击「打开需求」进入对应需求的详情。需求已不在活跃快照时，打开原系统页面；快照缺失不等于需求已删除。需求流刷新后共享状态更新，个人状态在 D板单独记录，正式流程通过需求流推进。

## 按周期自动开始

个人需求使用本机日期判断开始时间：待开始且开始日期已到，会进入进行中；尚未到开始日期仍待开始，只有截止日期不会自动开始。未填写截止日期可视为持续进行，超过截止日期也不会自动完成。

新建、保存、刷新和跨天/唤醒时检查周期，自动开始的状态写回本地缓存，并沿用原有同步流程。已完成、挂起和手动进行中的状态保留；需要恢复待开始时，先将开始日期改到未来或清空。表单状态与周期联动显示。

首页继续展示需要关注的需求；按周期进入进行中的需求会加入首页及进行中统计。需求流正式状态仍按其自身流程维护。

## 需求工程与业务地图

展开 ReqFlow 需求详情，在「涉及工程」中查看开发交付专用字段 `deliverableDevProject` 明确填写的工程和分支。未声明工程或分支时显示 `—`；不采用提交/PR 需求号、正文、文档或 AI 推断补齐，不通过业务地图建立需求工程关系。

进入需求流会读取「我的进行中」的开发交付，展开任意需求会读取该需求；区块内刷新按钮可重新读取。工程搜索覆盖已读取或已缓存的声明。来源和读取时间随工程显示，表示接口读取时间，不表示代码改动已核验或工程已全部列出。

声明单独原子保存到 `~/.claude/prd-development-projects.json`，刷新需求列表和重启不会清除。读取失败会提示错误并保留上次声明及其时间；成功读取但没有声明时清空旧值，避免旧工程被当作当前声明。上传交付成功后重新读取接口。

BizMap 继续保留服务文档入口、分组和参考信息；职责与关键词路由仅供参考。「生成时间」不是业务职责核验时间，刷新提交记录也不能证明职责和路由准确。

## AI 与技能运行策略

- 后台摘要/诊断：Qoder CN CLI + `Qwen3.6-Flash`。
- 直接接入的 AI 能力主要是资讯编译；当前没有通用 AI 对话入口。
- Codex 承担复杂日常任务、跨应用与本机操作；D板不会在 Qoder 失败时自动回退到 Codex。
- Zed 是代码与 Git 工作入口；选择 Qoder CN CLI 外部 Agent 时，Luban、R2C、LoongSuite Hooks 在 CLI 内触发。

模型、认证与组织策略以各自运行时为准。Skills 与 Context 看板展示运行时配置，不保存 API Key。
同名 Skill 安装位置合并显示，定义不同时标记并按各自运行时治理。
项目 `AGENTS.md` 是 Codex 与 Zed 原生 Agent 的规则；Qoder CN Memory 只服务 Qoder CN。
`CLAUDE.md` 与旧 Qoder Memory 作为迁移对照。

## 安装与验证

要求 macOS 15.0+、Swift 6.0+（Xcode Command Line Tools）。缺少某个后台 daemon 不影响其他模块。

```bash
cd /Users/zz/work/code/other/DBoard
swift test
./install.sh
```

安装脚本构建、打包、签名，安装到 `~/Applications/DBoard.app`，配置开机自启并重启应用。
导出只使用测试数据的深浅色布局检查图：


### 首页提交开发交付物

关联正式需求后，需求上下文中提供技术方案的查看／编辑和复制方案指令。方案由执行 AI 根据原咒言、追加变更、用户纠正及实际代码提前维护，正文只保存本机；用户编辑有自动草稿。代码、需求或开发分支变化后须核对方案，AI 不把旧 CR 和历史流水拼成正文。

点击“提交开发交付”先预览技术方案和源开发工程／分支，确认后才保存到[技术交付物汇总](https://alidocs.dingtalk.com/i/nodes/Qnp9zOoBVBZbY5railO7bDOeV1DK0g6l)，再提交开发交付物。缺少有效方案时先交给 AI 准备。预发兼容、集成和发布工作树单独记录，不覆盖源开发分支；工程名保留仓库原名。

同一需求更新方案复用原链接。修改远端前核对原正文，发现他人编辑则保留并提示核对；提交结果不确定时先查已有记录，避免重复提交。方案准备、文档上传、开发核验和正式验收彼此独立，交付不会改变需求状态。依赖本机 `dws` 登录、目录写权限及需求流 Cookie。

### 钉钉需求总览同步

「进行时」仅同步需求编号、名称、项目、状态、排期、正式需求链接、一两句话概括和最新有效进度。完整咒言、变更原文、图片、群聊、工程分支、进度明细、历史记录及零碎保存在本机。新增变更还没有对应反馈时，总览显示待处理提示。

同步依据生成后的总览内容判断变化。本地资料变化、仅反馈仓库或重复同步不再调用远端写入；手动同步可重新发布总览。同步过程中发生并发本地修改会保留新数据，需要时继续同步；只有确认成功才写凭证。旧的全文同步凭证会触发一次总览迁移。归档同样只输出简版，本机归档快照继续保留全部资料。

AI 可通过 `dboard-ai report ... --overview '需求范围概括'` 补充或更新概括，不必反复提交；`--summary` 写本轮实际进度，`--details` 保留交接明细。云端总览不作为本地缓存的恢复来源。
